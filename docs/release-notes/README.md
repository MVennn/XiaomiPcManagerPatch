# release-notes/

> **一句话**：面向使用者的 Release 说明模板与写法 —— 文件名 = 版本号（不带 `v`），
> 首行加粗总结、次行反馈入口、清单式正文、固定风险尾巴。

放**面向使用者**的 Release 说明，**文件名 = 版本号本身**（如 `0.1.0`），**不带 `v` 前缀** ——
`v` 前缀只属于发版 tag。版本号与 [CHANGELOG.md](../../CHANGELOG.md) 的段标题一致。

## 为什么要单独放一份

`CHANGELOG.md` 是**开发者记录**：症状 / 根因 / 改法 / 验证结果 / 踩坑。
Release 说明是**给使用者看的**，要短、写成清单、只讲「我现在能拿到什么」。

本仓的「使用者」是**想让小米电脑管家在非小米电脑上跑起来的人** —— 他关心的是：
「跑哪条命令能装好、哪几步需要管理员、出问题了查哪」。

## 形状

**清单，不是文章。** 开头一句加粗概述，`## 本版内容` 下按分区一行一条，最后是固定尾巴。
**第一行必须是加粗总结；紧接的那一行是反馈入口**（一行，链接用绝对地址），
然后才是 `## 本版内容`。

```markdown
**首版：把「非小米电脑装小米电脑管家」拆成三层补丁，一键脚本全流程打通。**

遇到问题、想要新版本适配，到 [Issues](https://github.com/MVennn/XiaomiPcManagerPatch/issues/new/choose) 反馈 —— 请附 Windows 版本、电脑管家版本、执行的完整命令与输出原文。

## 本版内容

**补丁**

- 新增 xpm_patch.py —— 安装包白名单字节等长补丁 + 运行时机型伪装。
- 新增 padgate_patch.py —— 平板镜像多显示器 / NVIDIA 拦截补丁，status / apply / restore。

**脚本**

- 新增 Install-XiaomiPCManager.ps1 —— 一键全流程，含 -ModelOnly / -NoLaunch。

**文档**

- 新增 架构与边界 —— 三层限制、会改什么、回退。
- 新增 踩坑总汇 —— 按现象查根因与解法。

---

需要 Windows 10/11、管理员权限、自备小米电脑管家官方安装包（实测 6.0.0.39）。
一键脚本会写注册表、改服务、给官方 DLL 打补丁，执行前请先看 [架构与边界](../ARCHITECTURE.md) 的「会改什么」。

---

> 风险提示：补丁版安装包原厂签名失效；程序自动更新会写回原版清单，届时重跑脚本。
> 详见 [架构与边界](../ARCHITECTURE.md) 与 [安全策略](../../SECURITY.md)。
```

结尾那两行是**固定尾巴**，每版照抄不动，**不算重复内容**。

## 反馈入口：写在开头，链接必须是绝对地址

每份说明的**第二行**放一行反馈入口，不是清单条目：

- 链接写绝对地址 `https://github.com/MVennn/XiaomiPcManagerPatch/issues/new/choose`
  —— 说明会被贴到 Release 页面，相对链接在那里解析不到；
- 已发布的历史正文**不回填**；这条规则只对**新版本**生效。

### 一条怎么写

```text
新增 / 调整 / 修复 / 优化 + 对象名 —— 入口或位置；一句话你拿到什么
```

- **动词只有四个**：新增、调整、修复（含底层与实现层）、优化；另有「移除」。
- **对象名照抄仓库里的实物**（文件名 / 文档名 / 脚本名）。
- **入口**写你找得到的位置：「仓库根 README」「docs/ 索引」；不需要找入口的写场景（「目标机上」）。
- **一句话说完你拿到什么**。不写怎么用、不写为什么。
- 一行一条。

## 覆盖率红线

**凡本版改过的东西，必须全部出现在 Release 说明里**，一行一条。没有例外。
写完拿 CHANGELOG 对应段落逐条对。

## 别写这些

| 别写 | 为什么 |
|---|---|
| 第二人称操作步骤 | 步骤归 README 与踩坑总汇 |
| 原因与取舍 | 解释属于 CHANGELOG |
| 实现原理、补丁内部机制 | 同上 |
| 「本版没有破坏性变更」 | 没变更就不用声明；**有**的时候才必须写 |
